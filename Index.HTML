Spotter — personal AI agent
● Live · in daily use
A deployed AI agent that runs 24/7 and takes real actions

Built to externalize executive function: it captures tasks, surfaces the next concrete action when something feels too big to start, drafts messages I'm avoiding, and calls me out when I'm stalling on a project. The motivation was personal — I built the tool I actually needed.

  • Tool-using agent with the LLM acting as router across 8 tools — no separate intent classifier
  • Layered memory in SQLite: a lean always-injected context plus on-demand full-text retrieval to control token cost
  • Proactive scheduling engine — morning brief, evening check-in, and natural-language reminders, with catch-up so a restart never drops a message
  • Built for production: tool-loop iteration caps, graceful error handling, and a persistent-volume database so state survives restarts

Glyph — RAG & vector-embedding pipeline
◆ Demo stage
Where I got hands-on with embeddings, retrieval, and re-ranking

A retrieval pipeline built to surface meaningful connections across personal memories. The motivation was personal here too — I wanted to gather my family's memories and learn more about our history.

  • Embeds unstructured content into a vector store (Pinecone) with metadata-scoped similarity search and dynamic top-k
  • Custom hybrid re-ranker on top of vector search — fuses similarity with entity and pattern overlap into explainable connections
  • A real judgment call: replaced a fragile initial scoring approach with a more robust hybrid method after testing revealed its limits

How I got here

Every project I've built started as a real problem in my own life — and each one taught me the next thing I needed to know.

About a year ago I was an infrastructure engineer, and I started using AI tools just to solve problems faster at work. It clicked quickly that I could build with them, not just ask questions. So I started building things I actually needed, and each project pulled me up the next rung: I hit the limits of one tool, so I learned web development; I needed things to run, so I learned to deploy them.

My learning is necessity-driven — I start with a real problem and learn whatever it takes to ship. That means I've learned exactly what shipping real things requires. And because I come from infrastructure, I think about reliability, error handling, and production behavior from the start — the AI systems I build work the same way.
